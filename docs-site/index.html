One consistent way to execute across your systems.

CRM, ERP, APIs, databases and AI agents should not each grow their own version of business meaning, validation and authorization. Foundgine is the configurable semantic and execution boundary between application capabilities and the interfaces that consume them.

Define meaning once.

Configure entities, fields, relationships and capabilities, then reuse them across application code, APIs, GraphQL and optional MCP callers.

Keep authority in the application.

Identity and policy stay with the host. Foundgine resolves and authorizes every operation before physical execution; an AI-generated request is never permission by itself.

Keep your existing stack.

Retain your domain applications, databases, EF Core or JPA, identity provider and workflow engine. Planning stays provider-independent until the execution boundary, so adoption can be incremental.

The business case is measurable: compare duplicated implementation, change effort, security-test coverage and operating cost before and after a representative pilot. Foundgine does not promise a universal percentage. Business and architecture case · Commercial strategy and measurement model

One lifecycle, many callers.

Application code, JSON, GraphQL, MCP and AI tools enter the same execution path. Retrieval can discover candidates, but it never becomes an authorization path.

  • Domain and semantic metadataWhat exists, what it means, and which capabilities are exposed.
  • AuthorizationDecided by the host’s identity and policy, before any plan.
  • Plan and ExecutionIRProvider-independent, with security provenance preserved through rewrites.
  • Providers and persistenceSQL, InMemory, EF Core and JPA/Hibernate do the physical work.

Open intent without open authority.

Foundgine gives AI agents a controlled capability surface without giving the model database authority. MCP is optional; the same boundary serves every other caller.

What the agent can do

  • Discover the capabilities the application exposes.
  • Express a request as structured intent.
  • Be asked to choose when candidates tie, instead of guessing.

What stays with the application

  • Authentication, actor identity and tenant context.
  • Authorization, re-evaluated for every actual operation.
  • Planning, validation and physical execution.

That run is not claim-grade, so it is not a published performance claim. Raw benchmark datasets are linked from the evidence pages rather than reproduced here.

Tests that attack the boundary.

Adversarial suites and runnable harnesses, in both .NET and Java, check that denied requests stay denied and that protected data does not change. Counts are test methods in the repository.

Penetration test suites

Intent red team Runs in CI

A low-privilege caller tries to infer hidden data through filters and ordering, confuse the parser, read internals from errors, spoof identity headers and see another caller’s results under concurrency.

13 tests in each language. .NET Java

Injection corpus Runs in CI

One shared set of hostile payloads is sent through the value, name and identity slots of an intent, so both languages face the same inputs.

13 tests in each language. .NET Java

Semantic boundary suites Runs in CI

Authorization escalation, tenant bypass, plan tampering, warrant replay, parser limits, secret leakage and provider conformance, each in its own test class.

59 .NET tests, 63 Java tests. .NET Java

MCP and GraphQL over HTTP Runs in CI

Adversarial requests go through both transports to a seeded PostgreSQL database: cross-tenant reads, restricted fields, claim injection and writes the caller may not make.

21 .NET tests. PenTest sample Source

Merge gates Runs in CI

Every suite above is a separate CI job. A single gate job fails the build if any of its jobs fails.

.NET: six jobs feed security-penetration-gate. Java: four feed java-security-penetration-gate. .NET Java

Live scanners Weekly

ZAP baseline and MCP protocol fuzzing run against the running .NET sample. Findings are informational and do not fail the build.

nmap and ZAP scripts also ship for both languages. Workflow Java scripts

Harnesses you can run

Java red-team harness Run locally

Four executable checks on the warrant model: replay, time validity, constraint attenuation and unknown invariants.

mvn -pl security/foundgine-redteam -am package Source

.NET AI red-team agent Run locally

One script starts PostgreSQL and the MCP APIs, then runs a bounded attack catalog against the semantic and execution endpoints. A model is optional, and the agent refuses non-loopback targets.

Run-Security.ps1 README

Strix and PentAGI agents No runs recorded yet

Two open-source AI pentest agents, pointed at the HTTP surface of both samples with identical scope. The harness is in place; results will be published once runs are triaged.

Harness Run log

Also in the overview: the chaos and clock harness and the Testcontainers CI harness.
